# DNS 请求与响应报文
在 DNS 查询中，迭代请求和递归请求的核心区别在于查询流程，但它们使用的 DNS 报文格式是相同的。DNS协议是属于应用层协议，基于UDP或TCP。

# 一、DNS报文基本结构
DNS报文由5部分组成。前两部分必须，后三部分根据查询结果动态填充。  
- Header(必须)
- Question(必须)
- Answer
- Authority
- Additional

1.头部，Header
```text
+---------------------+
|      ID (16 bits)   |    # 查询标识符（用于匹配请求和响应）
+---------------------+
| QR | Opcode | AA|TC|RD| # 查询/响应标志、操作码、权威答案等
| RA| Z  | RCODE       |
+---------------------+
|   QDCOUNT (16 bits) |    # 问题段数量（通常为 1）
+---------------------+
|   ANCOUNT (16 bits) |    # 回答段数量
+---------------------+
|   NSCOUNT (16 bits) |    # 权威名称服务器数量
+---------------------+
|   ARCOUNT (16 bits) |    # 附加信息数量
+---------------------+
```

2.问题段,Question
```text
+---------------------+
|   QNAME (可变长度)   |    # 查询的域名（如 "example.com"）
+---------------------+
|   QTYPE (16 bits)    |    # 查询类型（A、NS、MX 等）
+---------------------+
|   QCLASS (16 bits)   |    # 查询类别（通常为 IN）
+---------------------+
```

3.回答段,Answer
```text
+---------------------+
|   NAME (可变长度)   |    # 域名
+---------------------+
|   TYPE (16 bits)    |    # 记录类型（A、NS、MX 等）
+---------------------+
|   CLASS (16 bits)   |    # 类别
+---------------------+
|   TTL (32 bits)     |    # 生存时间
+---------------------+
|   RDLENGTH (16 bits)|    # 资源数据长度
+---------------------+
|   RDATA (可变长度)  |    # 实际数据（如 IP 地址）
+---------------------+
```

4.权威服务器段,Authority
```text
结构同 Answer，但存储权威 DNS 服务器信息（NS 记录）。
```

5.附加信息段，Additional
```text
存储辅助信息（如 A 记录对应的 IP 地址）。
```


# 二、递归请求的报文格式
```text
流程：client -> 本地DNS服务器(递归查询)
                                    -> root dns server
                                    -> TLD dns server
                                    -> authority dns server
             <-     返回结果       <- 返回结果 
```
